# Использование существующего сервера aranet4

Уточнение пользователя, 2026-10-08: сервер уже собирает и хранит данные. Основной путь — использовать его сборщики, историю и готовые прогнозы ИИ. Второй постоянный сборщик и отдельный набор погодных баз для приложения не нужны. Локальный backend в этом проекте остаётся средой разработки и проверки расчётов.

## Что подтверждено исходниками

`aranet4/deploy/server/setup.sh` включает серверные таймеры CyDoM, моря, официальных прогнозов, UV, воздуха и архивов; погодная история хранится отдельно от домашнего датчика. `dashboard.py` уже предоставляет погодные JSON маршруты станций, наблюдений, истории карты, UV, воздуха, моря, официального прогноза и прогноза ИИ. Генератор ИИ имеет отдельный серверный service/timer.

Это подтверждает архитектуру проекта. Фактическое состояние конкретного сервера пока не проверено: HTTPS адрес и порт не найдены в локальном checkout, config.env отсутствует.

## Что нужно приложению сверх исходного API

1. Публичный доступ только к погодным маршрутам по HTTPS. Исходный nginx применяет Basic Auth ко всему сайту. Для приложения нужен отдельный location/host с allowlist погодных маршрутов; домашние `/api/readings`, `/api/latest`, `/api/pressure-offset` и домашний UI должны сохранить защиту. Пароль нельзя встраивать в APK.
2. Совместимый API слой для `/api/weather/snapshot` (последние 6 показаний и давление с поправкой на высоту) и `/api/weather/model` (обычный почасовой прогноз). В проверенном dashboard.py таких маршрутов нет. Просто поменять VITE_API_BASE недостаточно.
3. Радиация соседней станции для графика должна быть доступна как отдельная измерительная серия; исходный API возвращает rad_src, но rad_global относится к выбранной станции.
4. CO: исходный air.py хранит измерения CO, но не отдаёт их в POLLUTANTS и не запрашивает модель CO. Приложению нужны оба ряда.
5. Прогноз ИИ берём из существующего API, если генератор уже работает на сервере. Не запускаем второй генератор на телефоне или локальном компьютере.

Эти дополнения можно обслужить небольшим погодным API процессом на том же сервере, используя существующую SQLite историю и существующий каталог ИИ. Для почасового прогноза потребуется либо подключить уже имеющийся серверный источник, либо добавить только недостающий сбор, без дублирования остальных источников. Совместимость схемы и миграции сначала проверяются на копии базы.

## Следующий шаг

Получить HTTPS адрес с портом; проверить доступность и фактические ответы погодного API. Затем локально подготовить точный адаптер и nginx конфигурацию для этого сервера, пересобрать Android приложение с правильным URL. Изменения на сервере, deployment, commit и push пока не выполнялись.

## Подключение локального приложения

`backend/remote_sync.py` читает только публичную погодную базу через SSH (SQLite read-only, согласованный snapshot в транзакции). Последние восемь дней измерений, UV и воздуха, бюллетени и последний ИИ-прогноз синхронизируются каждые пять минут. Адрес и пути задаются в gitignored `config.env` через `WEATHER_SSH_HOST`, `WEATHER_REMOTE_DB`, `WEATHER_REMOTE_AI`. `scripts/run-local.sh` автоматически выбирает этот режим. Сбор тех же источников локально отключён; отдельно остаётся почасовая модель Open-Meteo, которой пока нет в существующей базе. SSH доступ нужен компьютеру; APK всё ещё использует локальный API через USB. Для самостоятельного использования телефона потребуется доступный HTTPS weather-only API.

## Автономный HTTPS API

Развёрнут по адресу `https://11xsloperator.app:47613/cyprus-weather/api/`. Отдельные systemd службы `cyprus-weather-api` и `cyprus-weather-sync` включены в автозапуск. Код установлен в `/opt/cyprus-weather`, отдельная погодная база — `/var/lib/cyprus-weather/weather.db`. Существующая погодная база читается только read-only; домашняя база не используется. История синхронизируется каждые пять минут, почасовая модель — каждый час. ИИ-прогноз читается из существующего каталога.

Nginx публикует только `/cyprus-weather/api/` (GET); старый интерфейс сохраняет Basic Auth. Сертификат проверен обычным HTTPS запросом. Исходные сборщики aranet4 продолжают работать. Конфигурации находятся в `deploy/`; резервная копия nginx сохранена на сервере в `/var/backups/cyprus-weather`. Обновление: передать backend и deploy через SSH, проверить `nginx -t`, перезапустить отдельные службы. Откат: отключить эти две службы, убрать новый location nginx и reload.

APK собран с `VITE_API_BASE=https://11xsloperator.app:47613/cyprus-weather`; компьютер, локальный API и adb reverse для работы больше не нужны. Локальный web preview использует тот же адрес через gitignored `mobile/.env.local`.

API молний читает существующую публичную базу через `--lightning-db` в read-only режиме. Путь задан в отдельной systemd службе; существующий сборщик/доставка молний продолжают работу. Никакие EUMETSAT ключи в новый проект не копировались.
