# Cyprus Weather: оценка и план реализации

Дата: 2026-10-07. Решение принято до написания приложения.

## Уточнение после первой реализации

Пользователь сообщил, что сервер aranet4 уже собирает и хранит данные. Для приложения используем его историю и сборщики; локальный backend — среда разработки. Подробности и недостающие API: [EXISTING_SERVER.md](EXISTING_SERVER.md). Первоначальная оценка ниже сохранена как запись решения до реализации.

## Вывод

Переиспользуем погодное ядро aranet4, но создаём отдельный мобильный интерфейс и отдельный публичный API. Android: Capacitor 8 + JavaScript/Vite + ECharts/Leaflet. iOS: тот же интерфейс, отдельный native target Capacitor. Python остаётся только на сервере. Flutter/React Native потребовали бы переписать графики, карту и вычисления; для этого проекта выгода пока не оправдывает стоимость.

Это устанавливаемое Android приложение с локально упакованным интерфейсом, не ссылка на существующий сайт. Без Bluetooth, домашнего датчика, сравнения с домашними данными, входа и пароля. Backend обслуживает публичные погодные данные. Секреты провайдеров/ИИ остаются на сервере.

## Что проверено в исходниках

- `weather.py`: XML CyDoM, SQLite, единицы ветра, NET, UTCI, источники радиации, история карты.
- `thermal.py`: полином UTCI, солнечная геометрия и радиационная температура.
- `agg.py`: часовые/суточные агрегаты, суммы осадков и круговое среднее направления ветра.
- `uv.py`: CAMS UV и модель радиации; высота станции.
- `air.py`: DLI, CAMS и отдельная ближайшая измерительная станция для каждого вещества.
- `dom.py`, `forecast.py`: море, предупреждения, A/B/C, таблица, карта, сезонный и месячный PDF, кэш переводов.
- `ai_forecast.py`: серверный генератор, JSON схема; запуск через CLI требует отдельной настройки.
- `dashboard.py`: содержит маршруты домашнего датчика, поэтому не переносится целиком.
- `static/common.js`: солнечные вычисления; `weather.js`: карта и графики, но монолит тесно связан с домашним датчиком. Берём вычисления/библиотеки, UI делаем заново.

Исходный проект не изменяем. Вендорим выбранные модули и тесты с записью исходного commit и SHA256, чтобы приложение не зависело от соседней локальной папки. В исходном checkout нет отдельного LICENSE: перед публичным распространением нужно определить лицензию с владельцем. Локальная работа продолжается.

## Архитектура

`mobile/` — четыре вкладки, общая сворачиваемая карта, выбор станции, геолокация при запуске с разрешением ОС и повторным поиском по кнопке, графики в модальном окне, обработка ошибок и сохранение выбранной станции.

`backend/` — API на стандартной библиотеке Python, только погодные маршруты; SQLite, коллекторы и новый почасовой прогноз Open-Meteo. История накапливается независимо от телефона. API не выполняет внешние запросы при каждом открытии карточки.

`android/` — native target Capacitor. Для браузерного просмотра Vite проксирует `/api`; в APK URL HTTPS backend задаётся на этапе сборки. Для локальной проверки можно подключить backend через `adb reverse` и debug-only HTTP. Публичный сервер и HTTPS будут отдельным этапом: пользователь пока запросил только локальную работу.

## Контракт экранов

Общая карта закрыта по умолчанию. Станции, выбранная станция и ползунок последних 24 часов с почасовым шагом. Значение старше 60 минут не выдаём за текущее; пробелы остаются пробелами.

### Погода

Карточки: температура, UTCI в тени/на солнце и NET, ветер, влажность, осадки, давление, море. Для погодных карточек используются последние 6 показаний станции, не календарный час и не усечённое окно от текущего времени. Средние считаются по этим показаниям, осадки — сумма шести десятиминутных интервалов. Счётчики вида 1/6 и подпись неполного окна не показываются. При отсутствии полной шестёрки значения остаются недоступны; недостающие показания не выдумываются. UTCI: без текста «нет теплового стресса» в диапазоне 9…26 °C. Солнечный UTCI и подпись «В тени» скрыты, если текущая высота солнца ≤0°; значение UTCI в основной карточке сохраняется.

Графики: предыдущие 24 часа измерений + следующие 24 часа модели, почасово. Прогноз пунктиром, граница «сейчас», источник и единицы. Осадки — столбики сумм за час, вероятность осадков модели на второй оси; отсутствующий интервал не равен нулю. Ветер измеренный на 2 м обозначается отдельно от модельного на 10 м.

Давление: предпочитаем station pressure. Для пользовательской высоты пересчитываем через барометрическую формулу `p₂ = p₁ exp(−g Δh/(R T))`. Если у выбранной станции нет давления — ближайшая актуальная станция, имеющая давление и известную высоту. MSL/QNH не смешиваем со station pressure. Показываем станцию, расстояние, тип исходного давления, высоты и факт расчёта. Если высота пользователя неизвестна — целевая высота выбранной станции, явно подписанная; есть ручной ввод. Геолокационная altitude ненадёжна, это оценка, не точное измерение.

Море: значение из морского бюллетеня (региональное, не датчик выбранного пляжа), отдельная динамика по дням за 7 суток; прогноз моря не придумываем.

### Солнце

Текущее положение и восход/закат. Общий график: ближайший верхний или нижний экстремум в центре, ±12 часов, почасовые точки плюс точная отметка сейчас. Даты/время Asia/Nicosia независимо от timezone телефона.

Радиация + UV: две оси W/m² и UV. Измерения своей или соседней станции в пределах 15 км и 350 м высоты; без высоты максимум 10 км — правило aranet4. Если измерений поблизости нет, измерительную кривую не рисуем. Модель радиации при наличии показывается отдельно и используется для солнечного UTCI с указанием источника. UV всегда CAMS. Прошлые 24 и прогнозные 24 часа.

### Воздух

Шесть карточек: PM2.5, PM10, NO₂, O₃, SO₂, CO. График −24/+24 часа. Для каждого вещества подписана ближайшая DLI станция, её тип, расстояние и дата; CAMS показан как модель. В aranet4 отсутствует модель CO — добавляем её в переносимом модуле, иначе шестая карточка не имела бы прогноза. Не превращаем расстояние до транспортной станции в утверждение о точной экспозиции пользователя.

### Прогноз

A/B/C — три независимых свёрнутых блока. ИИ — таблица и текст внутри свёрнутого блока, без автоматического вызова платной/авторизованной модели. Таблица районов, сезонный прогноз и последний месячный отчёт раскрываются по нажатию. Карта на завтра видна сразу. Выводятся срок действия, время выпуска и оригинал при отсутствии перевода. ИИ отсутствует до настройки генератора; приложение сообщает это честно.

## Сбор и источники

CyDoM каждые 5 минут, прогнозы/море каждые 30 минут, UV/CAMS/почасовой прогноз каждый час, DLI раз в час с соблюдением crawl delay. Первый запуск не скачивает многолетний архив. Коллекторы изолированы: отказ одного не удаляет данные остальных. Старые данные и последний успешный сбор видны в UI/API.

Open-Meteo бесплатный endpoint имеет лимиты и рассчитан на некоммерческое использование. До публичного запуска уточнить лицензию, тариф/лимиты, правила DLI и атрибуцию; API вынести за HTTPS с кэшем и ограничением частоты. Переводчики исходника неофициальны — ошибка оставляет оригинал. Источники:

- https://capacitorjs.com/docs
- https://capacitorjs.com/docs/android
- https://open-meteo.com/en/docs
- https://open-meteo.com/en/docs/air-quality-api
- https://github.com/DarkPatrick/aranet4

## Порядок работы и критерии готовности

1. Этот документ и журнал происхождения кода.
2. Погодное ядро без BLE/домашних маршрутов; API, прогноз и давление; проверки на fixtures.
3. Четыре вкладки, все карточки, графики и карта; пустые/устаревшие данные и частичные ошибки.
4. Native Android target, сборка APK при доступном SDK. iOS target можно добавить позже на Mac с полным Xcode.
5. Локальные сборки и проверки; README с командами. Никаких commit/push/deploy.

Готовность проверяется реальной сборкой web/native, тестами расчётов и API и визуальным просмотром. APK без подключения к backend не содержит выдуманных погодных данных. Недоступный SDK/источник обозначается как блокер соответствующей проверки, не как завершённая работа.

Графики динамики используют скользящие последние 24 часа от текущего момента, а не период с полуночи. Прогноз — следующие 24 часа. Продолжительность сохраняется при смене даты и переходе на зимнее/летнее время.
