# Cyprus Weather

Android приложение погоды Кипра без домашнего датчика, Bluetooth, логина и пароля. Общий JavaScript интерфейс через Capacitor позволяет позднее добавить iOS target. Python используется только в погодном backend.

Оценка, решения и контракт экранов написаны **до реализации**: [docs/PLAN.md](docs/PLAN.md). Происхождение перенесённых модулей: [docs/UPSTREAM.md](docs/UPSTREAM.md), исходные hashes: [docs/UPSTREAM.json](docs/UPSTREAM.json).

## Существующий сервер

Основной источник приложения — уже работающий сервер aranet4. Дублировать его постоянный сбор не требуется. Локальный backend ниже используется для разработки и проверки; подключение к существующему серверу требует проверки адреса и совместимости API. [План подключения](docs/EXISTING_SERVER.md).

## Что реализовано

- Четыре вкладки: Погода / Солнце / Воздух / Прогноз.
- Свёрнутая карта станций, выбор станции, ползунок прошлых 24 часов, автоматический запрос геолокации при запуске и повторный поиск по кнопке с меткой. При разрешении выбирается белижайшая актуальная станция, при отказе сохраняется ручной выбор.
- Погодные карточки по последним 6 показаниям станции независимо от начала часа; без счётчиков измерений. Осадки суммируются. UTCI в тени/на солнце и NET; солнечная карточка и подпись «В тени» скрыты ночью, текст отсутствия стресса не выводится.
- Давление с ближайшего доступного источника, поправка на заданную высоту пользователя; без ввода высоты — высота выбранной станции. Источник и тип давления подписаны; график также пересчитан по высоте.
- Графики наблюдений −24 часа и модели +24 часа, прогноз пунктиром. Осадки — часовые столбики плюс вероятность на второй оси. Пропуски не соединяются линией.
- Море — региональный бюллетень и суточная динамика за 7 дней.
- Солнце, восход/закат, симметричный график вокруг ближайшего экстремума и текущая точка. Время всегда Asia/Nicosia.
- Радиация измерительной станции в разрешённой близости и UV CAMS с разными осями; модель радиации отдельно.
- Шесть веществ: PM2.5, PM10, NO₂, O₃, SO₂, CO; DLI и CAMS подписаны отдельно, CO добавлен к исходному ядру.
- Свёрнутые A/B/C, прогноз ИИ, официальная таблица, сезонный прогноз и месячный отчёт; карта на завтра открыта.
- Независимые коллекторы, сохранённая публичная история и статус источников; backend не вызывает платные модели при открытии приложения.

## Языки

Русский, английский и греческий: выбор по системе, сохранение ручного выбора, переключатель слева от темы. Словари интерфейса, погодные шкалы, названия станций и формат дат разделены структурно. [Устройство и проверка локализации](docs/LOCALIZATION.md).

На DO новые бюллетени переводятся через Codex на русский и английский, греческий сохраняется оригинальным. Тексты ИИ, отчёты и предупреждения также локализуются заранее. Неизменившиеся предложения используются из постоянного кэша; открытие приложения не запускает модель. [Фоновый перевод и API](docs/CONTENT_LANGUAGES.md).

## Локальный запуск

Из корня проекта:

```sh
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements.txt
npm ci
./scripts/run-local.sh
```

Интерфейс: http://127.0.0.1:5173. API: http://127.0.0.1:8092. Первый сбор занимает несколько минут. Если эти процессы уже запущены, откройте интерфейс; не запускайте второй API на том же порту.

По отдельности:

```sh
.venv/bin/python backend/server.py
.venv/bin/python backend/collect.py --loop
npm run dev
```

Обновить отдельный источник:

```sh
.venv/bin/python backend/collect.py --source stations
# sources: stations, uv, hourly_weather, air, marine, bulletins
```

История CyDoM не доступна задним числом: фид отдаёт текущие показания, поэтому для полных 24 часов сборщик должен непрерывно работать сутки. При первом старте график может быть коротким; карточки доступны после накопления шести показаний. На этой машине импортирована только публичная weather.db из aranet4; домашняя aranet.db не используется. Импорт на другой машине выполняется из явно указанного файла:

```sh
.venv/bin/python backend/import_history.py /path/to/weather.db
```

Все базы, SDK, Java, зависимости и результаты сборки gitignored.

## Android

Требуются Java 21 и Android SDK API 36. Для текущей локальной проверки они подготовлены в `.sdk/`, скрипт сборки использует их автоматически. На другой машине задайте `ANDROID_HOME` и при необходимости `WEATHER_JAVA_HOME`.

```sh
VITE_API_BASE=http://127.0.0.1:8092 ./scripts/build-android.sh
adb reverse tcp:8092 tcp:8092
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
```

Команды выше показывают режим локальной разработки через USB. Текущий `output/kairo-debug.apk` собран для автономного телефона с действующим HTTPS API. Повторить такую сборку:

```sh
VITE_API_BASE=https://11xsloperator.app:47613/cyprus-weather ./scripts/build-android.sh
```

Локальный backend и `adb reverse` автономной сборке не нужны.

HTTP разрешён только в debug manifest. Release app не разрешает cleartext; перед release следует проверить HTTPS URL и подписать AAB своим ключом. Никаких ключей подписи/аккаунтов в репозитории нет.

```sh

```

Нужны полный Xcode, signing team и HTTPS backend. Для геолокации добавьте `NSLocationWhenInUseUsageDescription` в Info.plist. UI и API общие; iOS target не создан и на устройстве iOS не проверялся.

## Прогноз ИИ

API читает `data/ai/latest.json` по формату aranet4: `{issued, model, forecast: {summary, situation, model_vs_obs, horizons, risks}}`. Интервальные карточки открывают текст в отдельном окне; таблица, сравнение с моделью и риски раскрываются отдельно.

Генератор перенесён и требует явно заданной команды/авторизованного CLI. Автоматически при сборе/открытии приложения он не запускается:

```sh
PYTHONPATH=backend .venv/bin/python -m cyprus_weather.ai_forecast --dry-run
# Сначала проверить prompt, затем вручную задать --cmd '<model CLI command>'
```

Использование CLI может расходовать подписку/токены. Спутниковые данные молний в этой версии не подключены, генератор явно сообщает это модели. Реальный ответ ИИ пока не генерировался.

## Статистика визитов

При каждом открытии приложение (и после возврата из фона через 30+ минут) отправляет `GET /api/visit?id=<uuid>`. `uuid` — случайный идентификатор установки в `localStorage`; сервер хранит только его и своё время, без IP и данных устройства, в отдельном файле `analytics/visits.sqlite3` рядом с погодной базой. Повтор одной установки в пределах 60 секунд не считается. Dev-сборки визиты не отправляют.

```sh
.venv/bin/python backend/visits.py stats --db /var/lib/cyprus-weather/weather.db --days 30
```

Для Google Play это нужно отметить в Data safety: «App activity» / «Device or other IDs», без привязки к личности.
